🌱 What is Green Software & How GMT Works?

1. Workload Awareness

Every line of code and computational loop requires electrical power. By measuring software during idle, light, and heavy phases, we understand its carbon footprint.

2. Hardware Telemetry

The Green Metrics Tool (GMT) uses hardware sensors such as Intel/AMD RAPL (Running Average Power Limit) to capture true Joules consumed by CPU and DRAM.

3. Container Isolation

GMT runs our containerized application inside isolated Linux cgroups, accurately attributing CPU core seconds and memory footprints directly to the container.

⏱️ Measurement Flow (usage_scenario.yml)

When submitted to the hosted GMT ScenarioRunner at https://metrics.green-coding.io/, the tool executes the automated phases defined in usage_scenario.yml:

1. Warmup & Health Check → Verifies HTTP 200 on /health 2. Baseline Idle (5s) → Captures baseline idle power draw 3. Lightweight Workload → GET /workload/light (low CPU impact) 4. Cooldown (3s) → System returns toward baseline 5. CPU Intensive Workload → GET /workload/heavy (high CPU impact) 6. Post-Run Cooldown (3s) → Captures post-execution stabilization
